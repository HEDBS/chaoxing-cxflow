# 风控（【9010】罚站）处置

## 一、先分清三种「反常」，处置完全不同
| 现象 | 判据 | 处置 |
|---|---|---|
| **掉线**（SessionExpired） | 最终 URL 落到 `passport2…/login`，或正文含「扫码登录/用户登录/手机号登录」，或 <1200B 的「温馨提示/提交失败/没有此页面访问权限」提示页 | 重载/重登 |
| **风控**（RiskControl，2026-09-29 实测 4527B 提示页） | 正文含 **`【9010】`**（形如「【9010】操作异常，请输入图片中的验证码」），或「提示页面」+ `processVerifyPng` | 冷却 → 重登 → 仍不行**人工过验证码** |
| **真没数据** | 接口 `code==0` 且列表空 | 报告 0 条（**只有这种才允许报 0**） |

⚠️ 最坑的历史 bug：风控页正则匹配不到内容 → 上层拿到空列表 → UI 显示「扫描完成 0 条」。
**静默 0 条 = 故障**：检测不到风控时，至少要用「账号有课但扫不到作业」做兜底归因并报错。

## 二、自愈级联（照抄，顺序不能换）
```
op()
 └─ 抛 SessionExpired/RiskControl
    → ① reload_cookies()        # 从磁盘重载 cookie，零网络请求，代价≈0（长连接实例中毒但磁盘态干净）
      → op()
       └─ 又抛
        → ② sleep(RISK_COOLDOWN_S=8) → recover_session()（备份 cookies.txt.stale + 删 cookie + 全新登录）
          → op()
           └─ 又抛 → 原样抛出（绝不静默吞）
```
- **为什么先冷却**：风控跟 **IP 热度**走。刚跑完几十个请求立刻重登，新会话会立刻再被拦（实测）。冷 8s 起，人工建议 1–2 分钟。
- **为什么先重载**：重登要打登录接口，本身也在增加风控概率；磁盘 cookie 通常已干净。
- **必须包壳的调用点**（裸 `raw_get` 是历史 bug 源头——日志「2 秒就失败」，自愈根本没跑）：
  `ensure_login` 的 stat2 探活、`getWorkStuUrl` 第一跳、`prompt` 领卷、每课扫描。
- **逐课扫描中途被罚站**：只做**免费**的 `reload_cookies` 重试一次；**不要**逐课重登
  （连发几十次登录请求会被限流，表现就是进度条冻住，实测踩过）。仍被拦 → 跳过该课并**记账**，
  末尾汇总「N 门课被风控跳过 —— 等 1-2 分钟冷后再扫一次即可补齐，不是没作业」。

## 三、验证码人工出口（**红线：不自动识别**）
```
GET  https://mooc1.chaoxing.com/processVerifyPng.ac?t=<随机>    # 绑定当前会话，必须同一个 Client
POST https://mooc1.chaoxing.com/html/processVerify.ac           # app=0&ucode=<4 位>
```
- 自动识别验证码 = 绕过人机验证，**不做**。只做「取图给人看 + 代提交」。
- **成败判据是回验**：提交后重新 GET `https://mooc1.chaoxing.com/visit/courses`，正文**不再含 `【9010】`** 才算通过；**不信响应文案**。
- 回验失败 → 提示「等 1-2 分钟再试，或到学习通 App/网页手动过验证码」。

## 四、降低触发概率（实战口径）
1. **限速**：扫课每课 0.6–1.4s、解题每题 1.0–2.5s、审核领卷 0.6–1.4s；**绝不并发**。
2. 别在同一账号上同时跑桌面版 + CLI + 浏览器多路请求。
3. 提交前先 `work/validate`：`status=2` 说明这时候要验证码，先过验证码再提交，别硬撞。
4. 长跑任务放夜里、单会话串行；一次性提交多份作业之间留间隔。

## 五、脚本行为

`captcha get` 取图、`captcha post --code` 回填（含回验）。
