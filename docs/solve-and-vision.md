# 解题与识图（提示词原文 + 判据）

## 一、后端链
- 后端 = 任意 OpenAI 兼容端点（`POST {base_url}/chat/completions`）。可多配，**按顺序降级**：某家报错/拒答 → 换下一家。
- 返回处理分裂点：一家坏（连不上/401/超时）＝ `provider_err` 换下一家；**一家拒答**（"请把题目发给我"）＝ `refused` 换下一家；全链都拒答 → 留空给人。
- **别把拒答当答案**：实锤过模型把 `(填空题,16.6分)` 当题面回「请把题目发给我」，被当成 ok 答案送进审批屏。拒不拒答用词表判：`看不到|没看到|无法确定|无法回答|请提供|请把|请您提供|需要看到|抱歉|sorry|i cannot|i need`。
- 温度 0，`max_tokens` 选择题 400 / 文本 800；限速每题 1.0–2.5s。

## 二、提示词原文（照抄，改动前先实测）

**单选/判断**（`CHOICE_PROMPT`）
```
你是答题引擎。从选项中选出正确答案。
先在内部思考，最后一行只输出一个字母（不要任何其他字符、不要括号）。

题目：{stem}

选项：
{options}

最后一行：
```
**多选**（`MULTI_PROMPT`）——多选**必须**出字母串，丢给文本生成会回来一整句话，提交即错
```
你是答题引擎。这是一道**多选题**，正确选项可能有多个（至少两个，也可能全选）。
先在内部思考，最后一行只输出正确选项的字母，按字母顺序连写（如 ABD）。
不要空格、不要逗号、不要其他任何字符。

题目：{stem}

选项：
{options}

最后一行：
```
**填空/简答**（`_TEXT_RULES` + 题型令，2026-09-29 用户要求）
```
作答规则（逐条遵守）：
① 只输出答案本身。不要开场白、不要收尾总结、不要解释你在做什么，不要任何 markdown 标记（**、##、- 列表）、不要 emoji。
② 像学生自己手写的答案：句子短，直说结论和理由，可以用「因为…所以…」「也就是说」这类直白说法。
③ 禁用这类套话：首先/其次/再次/最后、综上所述/总而言之、值得注意的是、在一定程度上、具有重要意义、有效地、从而、进而、随着……的发展。
④ 简洁优先：一句话能答清就一句话，别为显得全面而分点罗列或排比铺陈。
⑤ 要能手写成纯文本：矩阵按行空格分列、换行分排；分数写成 9/2 这种。

<填空题：共 N 空。每空只写答案本身（一个词/一个数/一个式子），不要写成句子、不要解释；每行一个答案，按顺序对应每个空。
 | 简答题：用平实的话直接回答，写成一小段就行，不要小标题、不要分点罗列、不要「首先其次」。>

题目：
{stem}
```
> 为什么必须写进提示词：模型默认输出「首先…其次…综上所述」+ 分点 + 加粗，一眼不是学生写的；
> 学习通多为 **AI 评分**，实测平实纯文本拿高分，富文本反而不占优。

## 三、答案提取（别用「随便抓一个字母」）
1. 显式标签优先：`正确答案[是为:：]X` / `答案[是为:：](X)` / `Answer: X`；取**最后一次**匹配。
2. 独立的最后一行整行就是一个字母（可带括号/句点）。
3. 兜底：全文**独立**字母 token（`(?<![A-Za-z])([A-G])(?![A-Za-z])`）从后往前，且在选项集合内。
多选同理，只是匹配字母串（`ABD`），必须有 ≥2 个字母才收。
- 判断题：模型给字母（A/B）→ 用页面 `judge_map` 还原成 `true/false` 再提交。

## 四、置信度与人工闸门
| 来源 | confidence |
|---|---|
| 文本模型直答选择题 | 0.8 |
| 文本生成（填空/简答） | 0.6 |
| 图题 + local_vlm（PaddleOCR-VL） | 上限 0.8 |
| 图题 + 云 vision_api | 上限 0.75 |
| 图题 + RapidOCR | 上限 0.6 |
| 人工填写 | 1.0 |
- 低于 `confidence_threshold`（默认 0.75）＝ 低置信，**留空进人工审批**，不硬交。
- 状态机：`ok` / `need_manual`（图识别全挂、选项没解析出来、要求手写）/ `refused` / `provider_err` / `failed`。

## 五、什么时候该走识图（别把图片题喂文本模型）
- 触发条件：`image_flag`（题干里有 `<img>`）**且** 剥掉 `(填空题, 16.6分)` 这类 boilerplate 后
  **实义字符 < 8** → 题干实质内容在图里。
  （旧阈值 4 且没剥 boilerplate：`填空题166分`=7 字符 >4 → 图片题漏进文本模型 → 模型拿题型标记当题面答「请把题目发给我」。）
- 题图下载：GET `https://p.ananas.chaoxing.com/star3/origin/<hash>.png`，带 UA + `Referer: https://mooc1.chaoxing.com/`；`//` 开头补 `https:`。

### 识图链（优先级从高到低，任一出文本即止）
1. **本地 VLM：PaddleOCR-VL-1.6（llama.cpp / llama-server，OpenAI 兼容）**——免费离线无限，**主引擎**。
   请求体固定：`{"model":"paddleocr","temperature":0,"max_tokens":1500, "messages":[{"role":"user","content":[
   {"type":"text","text":"OCR:"},{"type":"image_url","image_url":{"url":"data:image/png;base64,…"}}]}]}`
   ⚠️ **prompt 必须就是 `OCR:`**。约束型 prompt（「逐字转写/不要纠错」）实测**更差**：会冒 HTML 转义并丢行。
   线代/公式图输出完整 LaTeX（`pmatrix`/`frac`），3–20s/张（多数 5–8s）→ timeout 给 120s，调用是阻塞的。
   已知系统性偏差（语义脑补、字符混淆、多空格压缩）在 prompt 层修不动，接受。
2. 本地 OCR（`rapidocr-onnxruntime`，零联网零成本）——纯文字题面尚可，公式/矩阵常读散。
   判脏启发式（命中就转云端）：含 `|`/`｜`、上标残留（`²³¹`、`^n`、`A2`）、纯数字孤行占比 >30%、
   出现「设 X=」却没有任何 `(数字` 开头的矩阵体。
3. 云多模态（任意 OpenAI 兼容 vision 端点，如 Qwen-VL）——**只做兜底**：实测会因模型下架(400)/免费额度耗尽(402)整条挂掉。
4. 全挂 → `need_manual`，UI/报告给原图人工填，**不猜题**。
- 本地 VLM 出的文本**不判脏**（LaTeX 里本来就有 `|` 和 `^`，误判会把好结果丢掉转云兜底）。

## 六、手写题（不能自动作答）
题干含这些词 → 标 `handwrite`，仍算「可作答/可领卷」，但**禁止进解题队列**（要人工写/拍照上传）：
`手写 / 写在纸上 / 纸上作答 / 纸质 / 拍照上传 / 上传照片 / 上传图片 / 拍照提交 / 拍照作答 / 附纸`

## 七、cxflow 与完整实现的差异
`scripts/cxflow.py` 是单后端 + 单遍解题的轻量版：无多 provider 轮换链、无 RapidOCR 判脏、
无多轮重试；选择题置信度固定 0.8、文本 0.6。要完整能力就用完整实现的 solver/providers（多后端轮换 + OCR 判脏）。
